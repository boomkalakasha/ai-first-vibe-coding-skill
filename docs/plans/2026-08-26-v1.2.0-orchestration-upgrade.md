# AI-first v1.2.0 升级方案与验收边界

## 目标

把已经在本机 Skill 中验证过的分层模型、多 Agent 并发治理、长上下文防漂移和正式业务写入审计能力整理为公开、可复用、可评测的 v1.2.0；保持 v1.1.x 的基本触发和 GitHub 开源发版兼容。

## 非目标

- 不把某个模型名称、宿主实现或公司内部流程写死为 Skill 规则。
- 不把公开 Release 当作生产部署、客户交付或数据库写入证明。
- 不把本机账号、路径、内网地址、Cookie、token 或项目业务数据带入仓库。

## 主要变更

| 领域 | 产物 | 验收重点 |
|---|---|---|
| 多模型协作 | `references/multi-model-orchestration.md` | Controller/Implementer/Reviewer 能力分层、唯一台账、Wave 重锚、P0/P1 门禁 |
| 研发闭环 | `references/end-to-end-workflow.md` | 应用地图、Spec、Case、业务审查、回测和复盘形成追踪链 |
| 并发治理 | `templates/execution-ledger.md`、`templates/iteration-manifest.md` | 跨窗口不可见时记为 UNKNOWN，保留 Controller/Reviewer 槽位，逐 Wave 扩容 |
| 业务安全 | `templates/business-write-path-inventory.md` | 全入口/回调/任务审计，唯一策略源，旁路负向 Case |
| 可交接性 | `templates/handoff.md`、`templates/task-baseline.md` | 授权、证据、风险、未完成项和下一轮可复用 |
| 评测 | `evals/evals.json`、`evals/trigger-evals.json`、`evals/runs/` | 行为与触发边界可复现，DOCUMENTED_ONLY 不冒充宿主运行通过 |

## 验收矩阵

- 静态：UTF-8 无 BOM、相对链接完整、公开风险扫描无内部标识、JSON 可解析。
- 行为：`validate.py`、单元测试、`run_evals.py` 和打包脚本全部通过。
- 评测：分层模型闭环和动态并发均保留 RED/GREEN/REFACTOR 证据，明确人工评测边界。
- 交付：版本、CHANGELOG、README 双语说明和 GitHub Release profile 一致。
- 证据：未观察到的宿主安装、运行态或生产行为必须标为 `DOCUMENTED_ONLY`、`NOT_RUN` 或 `NOT_VERIFIED`。

## 发布门槛

只有当前分支完整测试、公开风险扫描、精确 tag 构建、Release 资产和校验和均通过，且 PR/CI/仓库设置的外部证据已单独核验，才允许将候选提升为公开 Release。任何未关闭 P0/P1、阻塞项或旧失败 Case 都阻止放行。
