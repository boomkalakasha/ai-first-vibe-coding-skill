# Architecture-method evolution

Status: Unreleased source change; public version remains 1.3.3.

## Decision and scope

Keep architecture optimization within AI-first Vibe Coding's existing
repository workflow. Its responsibility is reusable methods for bounded
implementation, independent judgment, verification and learning. Keep Java
generation and executable harness capabilities in the
[Icarus Harness Java Scaffold](https://github.com/boomkalakasha/Icarus-harness-java-scaffold)
companion, public-readiness governance in its existing companion, and report
presentation in available report capabilities. This scope needs no new Skill
or repository.

The canonical method is [architecture optimization](../../references/architecture-optimization.md).
It owns the harness definition, document ownership and reference map, thin
path-selected host entrypoints and complete approved-scope integration. Existing
[context rules](../../references/workspace-records.md) own trustworthy reuse,
re-anchoring, durable records and goal semantics;
[promotion rules](../../references/skill-promotion-and-feedback.md) own learning.
Routing and templates link to these owners rather than copying a full method.

## Expected effect and tradeoff

Make relevant context reachable without forcing every directory to have an
AGENTS or document suite. Reuse full canonical specs and valid unchanged
context, while reading changed contracts and preserving unresolved decisions.
Enable a golden path first, then integrate the entire approved scope. These
are instruction changes; they do not add a scheduler, monitoring service,
domain runtime or host-loading guarantee.

The concise method reference adds a routing hop for architecture tasks.
Detailed workflow references remain available; no existing public tag,
license, package identity or release version changes in this source revision.
Private project evidence and local adaptation metadata are excluded.

## Validation boundary

[Behavior scenarios](../../evals/evals.json) distinguish coverage from guide
creation, explicit body loading from links, intermediate milestones from full
scope, unanswered intent from authorization, and autonomous details from goal
ambiguity. Their [rubric](../../evals/rubric.json) remains DOCUMENTED_ONLY;
configuration checks do not execute a coding-agent host.

Run the repository's complete local gate and review current tree/history
boundaries before delivery. Any separate smoke trial must retain actual
outputs and limits. A synthetic explicit-invocation trial cannot establish
automatic triggering, cross-host behavior, measured performance or adoption.
