# 上下文、意图与持续记录

## 必要基线与可信复用

实质工作前读取当前请求、最近作用域指南、有效项目总览/任务摘要、相关长期决定及可用的最近同类记录，核对影响本次结果的事实。普通局部任务只读相应指南、目标文件和必要验证入口；关键契约读相关完整正文，链接不等于已经加载，截断时补读缺失条款。

三类用户锚点职责分开：操作偏好拥有协作方式；项目全景拥有归属和环境事实；长期决策拥有已接受/否决方向与理由。具体路径由宿主入口提供，公共 Skill 不保存私人路径。不可达或缺失来源显式保持未知，继续不依赖它的工作，不猜测接口、权限或数据契约。

同一会话已读资料有可信未变依据时复用。任务转向、上下文压缩、跨会话、长时中断、相关来源/决定变化或冲突后，重读当前摘要与受影响事实；不沿用旧写集、旧 PASS 或旧运行状态，也不为此重新遍历全部历史。用户明确替换或取消目标时更新当前目标及允许影响，保留旧任务恢复线索；状态询问和普通补充仍服务当前任务。

## 授权与目标语义分别判断

用户当前执行请求可构成对应对象、动作和范围的授权；范围和风险未变时不重复申请。目标明确后，授权内常规、低风险可逆实现选择由 Agent 自主完成，必要假设简述。历史流程不是常驻操作许可；缺失凭据、权限或外部决定仍需解决。

当表述实质矛盾或关键文字疑似误写，且不同解释会改变实际结果时，指出冲突、提出必要问题并等待答复。可逆、最新措辞、提问已发出、工具成功、超时或无答复都不能替代答案；期间只推进不依赖答案的工作。用户明确改变旧决定时直接按新目标执行，不重复确认。仅高置信且不改变含义的语音、拼音或错字可规范化。

保留待澄清问题、已知解释、依赖它的动作和当前状态，压缩或交接后仍须遵守。技术测试只能证明选定实现的行为，不能证明 Agent 擅自选择的目标符合用户意图。

## 最小、持久、可恢复的记录

非简单任务必须有可恢复的项目总览及有标题的任务记录。优先更新已有等价记录，缺失时补最小内容：目标/范围、允许影响、必要来源、实施状态、实际验证、决定/未决项及下一步。可以引用已维护的项目事实，不因“不新建文档”把进度只留在聊天，也不要求每轮填整套模板。

PRD拥有结果与需求，ADR拥有长期选择及理由，行为Case拥有验证规则；逻辑职责分开，文件数量按实际影响决定。记录关键决定的依据、置信度、可逆性和待决项。小任务用三项卡片或已有记录；复杂任务按依赖和风险补环境与恢复信息。资料归属和引用式地图见[架构优化方法](architecture-optimization.md)。

交接从当前摘要和新事实重新定位。保留未答问题与依赖、已完成项及尚未覆盖的批准范围；不能用旧 PASS 或历史授权代替当前事实。

稳定知识保留范围、来源、日期、状态及替代/过期信息。临时事件留任务；机器事实留私有锚点；通用方法经复用、时效和脱敏检查后才进入 Skill。
