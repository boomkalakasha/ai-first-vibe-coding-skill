# 主动能力路由

按任务需要选择当前宿主实际可用的能力，先读入口说明再用；不可用时记录替代证据，不把名字写成已经安装或已经调用。

| 当前工作 | 评估的能力 | 触发依据 |
|---|---|---|
| 已有仓库实现、联调、复盘 | 本 Skill | 需求、实现、验收需要保持一致 |
| 需求不清、新产品/前端 | 产品需求、产品设计、前端构建相关 Skill | 用户结果、范围或界面需要成形 |
| 复杂设计、调试、验证、适合独立分工 | 对应 Superpowers 能力 | 存在实际计划、故障、验收或协作问题 |
| 真实页面、视觉或交互验收 | 宿主浏览器能力及适用浏览器 Skill | 需要观察 UI；纯源码任务不强开浏览器 |
| 文档、表格、演示、PDF、图像 | 对应工件 Skill | 交付物格式与渲染需要专门处理 |
| 数据库、部署、第三方服务 | 对应技术/服务 Skill | 当前任务需要该契约，且已授权对应动作 |
| Skill 恢复、编写、修改 | skill-creator / writing-skills 等可用能力 | 需要调整可复用指令和验证其效果 |

记录实际选用项、理由、跳过项与必要的降级，轻任务可在任务卡中一句话表达。最终回答末尾简述实际使用的 Skill/插件及作用，不列未使用项。

浏览器选择遵循当前用户偏好、宿主能力和工具边界。需要登录态时先核对可复用的授权会话；隔离实例使用独立 profile。只处理本任务拥有的标签页、进程和临时数据。远程调试不等于 headless；工具不可连接也不能绕过明确拒绝的访问授权。

多 Agent 主动评估收益，按独立工作包和可用容量安排；角色和数量服从平台能力与项目契约。不要把技能目录清单变成强制依赖，不把简单任务扩成全员并行。
